# Native online interface

`ramulator2-online CONFIG.yaml REPORT.yaml` accepts a full Ramulator2 memory configuration plus an `online` mapping. The native executable creates its own frontend with one source-statistics entry per physical stage across all replicas.

The mapping contains `accelerator_ghz`, `batch`, `replicas`, `warmup_requests`, `measure_requests`, `max_inflight`, `request_slots`, `request_stride`, `activation_replica_stride`, `dram_capacity_bytes`, `handoff_gbps`, `handoff_bytes_per_request`, `max_cycles`, and `stages`. Defaults measure fifty completions with zero excluded warmup requests. `mode` selects `pipeline` or `baseline`. Baseline compiler programs allocate the full per-replica array count to each stage, and the engine admits one complete microbatch at a time per replica. An optional `event_log` path enables JSONL causality logging.

Each stage contains `name`, `kind` (`prefix` or `dit`), `cores`, `timestep_start`, `timestep_count`, and `operations`. Prefix programs process single requests, with completed outputs collected at the first DiT stage. DiT microbatches retain their request identities through all assigned timestep iterations. Incoming stage queues hold up to `queue_capacity` requests, default twice the microbatch size. Downstream reservations include transfers still occupying the shared handoff link.

Operations contain unbatched dimensions `m`, `n`, `k`, `count`, byte addresses `a_base`, `b_base`, `c_base`, word size, K/N tile size, an optional `m_tile` row extent, and a `compute_costs` list containing `{m,n,k,cycles}` for every supported edge tile. Learned matrices set `b_shared=true`. Their microbatch rows concatenate and their weight addresses remain identical across stages and replicas. Attention products set `b_shared=false`, preserve independent request matrices and optionally set `rhs_share=8` for MQA. `b_transposed` represents a transposed matrix view through row-major address generation.

`a_instance_stride`, `b_instance_stride`, and `c_instance_stride` select distinct repetitions or layers. Request-local arrays add a reusable request-slot index times `request_stride`. Stage-local arrays set the respective `a_stage_local`, `b_stage_local`, or `c_stage_local` flag, then add replica index times `activation_replica_stride` and microbatch sample index times `activation_sample_stride`. Request slots are returned only after the corresponding action chunk completes. DMA addresses are checked against the configured capacity.

Each array lane retains an output tile across the K loop. Its two input buffers prefetch independent K tiles subject to the stage-wide DMA quota. The SRAM check covers both BF16 input buffers and an FP32 accumulation tile. Larger M extents keep a complete microbatch within one row tile when capacity permits. A tile begins computation after all of its accepted reads complete. The final K tile emits output writes, whose callbacks gate lane retirement. Operation barriers retire all array lanes before the following operation starts. A shared handoff-link serializer gates downstream readiness.

JSONL issue-attempt events precede the Ramulator call. Accepted issue events and completion events use the same tile token. Coalesced write callbacks can execute synchronously, so an accepted issue event can appear after its completion event at the same cycle. Request timestamps remain causal. Logging is optional to keep full-model runs bounded in storage.

Reports contain measured request latency and interval metrics, per-stage queue and DMA counters, read completion latency, memory stalls and service time, plus native controller statistics. Counters reset at the warmup completion boundary while pending requests retain their correct callbacks. Service time includes the complete duration of jobs finishing within the measurement window. Transaction counters satisfy initial outstanding + accepted = completed + remaining outstanding. Bandwidth uses completed transaction bytes within the clock window. Successful reports require the complete measurement to finish within the configured cycle budget.

`mode=isolated` calibrates one prefix or DiT stage in a fresh memory system. `calibration_batch` selects the prefix calibration batch. DiT calibration starts at its configured timestep and finishes at that stage’s timestep boundary. These jobs provide native uncontended service references for stage contention slowdown.
